## 동작

- 기본 꺼짐. 끄면 4.1.0과 같은 생성 요청을 보낸다(오프라인 body 비교 확인).
- 켜면 다섯 질문을 한 번에 생성한다. 등급 엔진·분야·난도 안내는 유지하고 공개 출력 필드만 줄였다.
- 작성 도움 만들기를 누른 카드만 추가 1회 요청한다. 질문/등급/ID는 응답에서 덮어쓸 수 없다.
- 작성 도움은 현재 선택 모델을 사용하며, 생성 당시 언어를 보존한다. 원질문만으로 도움을 만든다. 원본 메모를 다시 끌어와 질문을 재작성하지 않는다.
- 생성한 도움은 팩 및 보관 카드에 저장된다. 다시 펼치거나 재열 때 재요청하지 않는다. 편집된 질문에 늦게 도착한 도움은 적용하지 않는다.
- 취소·오류·화면 닫기 때 원질문과 기존 팩 유지.

## 비교 조건과 비용

4모델 × 2조건 × 2방식 = 16팩80장. 각 조건에서 다섯 카드 모두 완료된 backend 시간을 측정했다. 첫 token/미리보기 시간이 아니다. 모달의 300ms 준비 지연과 렌더 시간은 이 표에 포함하지 않는다.

기본: 카페 선호 메모/일상/난도1/low. 전설: 약속에 자주 늦는 친구 메모/철학/난도5/medium. 각 쌍 source/settings/seed 동일, full/first 순서를 교대했다. 조건당1관측이라 속도·품질의 통계적 일반화는 하지 않는다. GPT Pro OAuth 및 Claude 구독 CLI를 사용했고 Gemini는 제외했다. CLI 내부HTTP재시도는 관측 불가하다.

최초 생성16회+전설 첫 카드 도움4회=실제20요청. 실패0, 자동재시도/AI judge0, 좋은 출력 선택·대체0. 동결 ENGINE.cjs/PLAN.json/RESULTS.json에 요청 본문과 공개 응답/usage가 보존된다.

## 질문 품질 관찰

작성자가 모든80문항을 읽은 비블라인드 정성 관찰이며 사람 만족점수나 독립 AI판정이 아니다. 질문 먼저에서도 책임/신뢰/규범/측정의 근거를 묻는 논제가 남았다. 다만 품질 비퇴행을 입증한 것은 아니다.

- 질문 평균 길이는 기존 61.5자 → 질문 먼저 72.5자. 8조건 중 7조건에서 평균이 늘었다. 길이는 품질 점수가 아니지만 장황함 검토 근거다.
- Sol 전설은 기존의 짧은 논제보다 질문 먼저 쪽에 조건 설명이 길어졌다.
- Luna도 질문 먼저에서 전제가 길게 붙는 경향이 있었다.
- Sonnet 기본의 공부 효과 전제, Opus 기존 기본의 덜 딴짓 전제 등 원문에 없는 효과를 질문에 놓는 문제는 양쪽에 남았다.
- Opus 도움에는 사용자가 실제 지각 경험을 갖고 있다는 전제가 남았다. 도움4건의 질문 불변은 확인했으나 도움 의미 품질 전수 보증은 아니다.
- 따라서 속도 이득은 관측되었으며 기본off 실험 토글 후보로 보존한다. 기본on 전환/공개출시/품질성공 주장은 이번 결과에 포함하지 않는다.

## 기능 검사 및 수정

최종 로컬 검사: 123 tests, TypeScript, production build, secrets 검사, version 정합성 통과. 이는 질문 매력이나 교육 효과 검증을 뜻하지 않는다.

토글 저장·기존설정 기본off·preset 유지·카드5장·도움 지연·질문불변·취소/오류·저장왕복·다른팩/편집질문 보호 검사. Obsidian 임시 QA플러그인에서 외부모델 없이 실제 컴포넌트를 열어 on/off, 도움 요청1회, 재펼침0회, 보관뒤도움반영, 취소, 실패, 화면닫기후늦은응답무시 확인. QA플러그인은 제거하고코드를관리작업디렉터리에보관했다.

최초TypeScript union/parameter property 오류는 기능검사 중 교정했다. 실험 후 도움말 template 재구성 시 기존 seed를 잃던 로컬 메타데이터 문제와 생성설정 표시를 수정했다. 생성/도움의 모델 요청 본문은 변경하지 않았으며 의미결과를 재시험으로 대체하지 않았다.
